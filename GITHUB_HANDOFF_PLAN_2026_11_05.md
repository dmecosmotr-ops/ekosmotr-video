# Передача кабинета камер через GitHub — 05.11.2026

Цель: подготовить отдельный проверяемый проект для программиста компании, сохранить его в выбранном владельцем закрытом GitHub-репозитории и зафиксировать коммит. Программист сам проверяет изменения и разворачивает их на сервере. Прямой доступ к серверу не запрашивается; автоматического деплоя нет.

Основание: кабинет и ручной онлайн одной камеры проверены; UX-внедрение — `UX_UPDATE_2026_11_05.md`. Эта поставка не добавляет ИИ, непрерывную запись, полный архив Xiaomi или готовность 70 потоков.

## Проверяемый результат

- Исходники и зафиксированные зависимости собираются вне Windows-путей. Стенд запускается в отдельном контейнере, с собственным томом данных, лимитами ресурсов и портом только на loopback сервера.
- Серверный режим не создаёт известных тестовых пользователей и не показывает кнопки их входа. Первый администратор создаётся из отдельного секрета; секреты не в Git. Сохраняются CSRF/Origin/session/RBAC, добавляется явная конфигурация внешнего HTTPS-адреса.
- У контейнера нет privileged/host network/Docker socket/системных каталогов сервера. Автоматические workflows только тестируют и собирают, не подключаются к инфраструктуре компании.
- В Git попадают только исходники приложения и инструкции. Приватные Xiaomi-конфиги, видео/аудио, БД, логи, runtime, скомпилированные сторонние классы и node_modules исключены и проверены перед коммитом.
- Описано, что программист должен проверить/задать: порт, адрес, каталоги, ресурсы, администратора, резервирование, настройки видео. Видеоприёмник отделён от кабинета; неперенесённые или лицензионно неустановленные зависимости явно перечислены.
- Существующий локальный пилот и его пользователи остаются рабочими. Проверки серверного режима используют только временные данные.

## Зоны ответственности

1. Backend worker: безопасный серверный режим, конфигурация, bootstrap администратора, origin/cookie/bind, контракт признака тестового входа, tests. Файлы `backend/config.mjs`, `server.mjs`, `app.mjs`, `store.mjs`, `security.mjs`, `tests/deployment.test.mjs`. Frontend root скрывает тестовые кнопки по серверному контракту.
2. Packaging worker: `Dockerfile`, `compose.yaml`, `.dockerignore`, `.env.example`, корневой `package.json`, `.github/workflows/ci.yml`, `deploy/` и документация запуска. Никакого авто-deploy и секретов. Без изменения приложения/backend/frontend.
3. Portability reviewer: независимый read-only разбор состава видео, зависимостей/лицензий/путей и проекта. Свой файл `docs/VIDEO_DEPLOYMENT_REVIEW.md`. Затем review изменений остальных зон. Никакого чтения private и загрузки сторонних transport-бинарников.
4. Root: GitHub/репозиторий и Git, frontend-признак тестового входа, allowlist сборки, секрет-сканирование, сверка артефактов, общие тесты/сборка, итоговая инструкция и коммит. Не публиковать, пока владелец не указал репозиторий; продолжать независимую подготовку.

## Контракты и решения

- `createApp()` без серверного режима сохраняет прежний локальный стенд, чтобы не ломать текущую приёмку. Серверный режим задаётся явно через `PILOT_DEPLOYMENT=server`; unsafe/missing configuration отклоняется до открытия порта.
- Серверный `GET /api/session`/login возвращает `demoLoginAvailable:false`; локальный возвращает true. В браузер не передаются bootstrap-секреты.
- Серверный запуск принимает `PILOT_PUBLIC_ORIGIN` (один точный HTTPS origin), отдельный файл пароля администратора, собственный том данных. Reverse proxy компании завершает HTTPS; publish Docker ограничен `127.0.0.1`. Forwarded-заголовки не заменяют доверенную конфигурацию origin.
- Неразрешённый транспорт видео не прятать в образ и не скачивать автоматически. Приложение должно корректно запускаться с отключённым live; для существующего диагностического live — прозрачный отдельный путь подключения и перечень ограничений.
- Исходный проект не был Git checkout. Создан отдельный Git-корень камеры, без родительского аудиопроекта; код опубликован в закрытом https://github.com/dmecosmotr-ops/ekosmotr-video. Доступ GitHub-приложения ограничен этим репозиторием по отдельному подтверждению владельца.
