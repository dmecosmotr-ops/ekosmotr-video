# Экосмотр: проверка удобства кабинета — 03.11.2026

## Вывод

Пилот уже позволяет проверить основные функции, но для ежедневной работы требует лишнего чтения и выбора. Главной точкой входа должен стать адрес ПТО. Следующий уровень — нужный показатель или видео, затем подробности конкретной камеры.

Спокойный визуальный стиль, левое меню, поиск станций, отдельные вкладки онлайн/архива и парные заезды стоит сохранить. Основная работа — порядок информации, понятные названия и честные состояния данных. Добавление новых графиков сейчас менее полезно.

Это экспертный аудит, а не исследование поведения реальных региональных руководителей. В браузере проверен кабинет администратора; предложения для других ролей дополнительно сверены с исходниками двумя независимыми проверяющими. Рабочий код, учётные записи, права, Xiaomi и исходные таблицы не менялись. В ходе аудита новые видеосеансы не запускались.

## Задание и границы

Цель: найти, что мешает руководителю быстро ответить на три вопроса: какой ПТО нужен, что произошло за выбранный день, где открыть доступное видео.

Проверяемый результат: текущие экраны с доказательствами, приоритетный список правок, предлагаемая структура событий и критерии приёмки следующей версии. Источники: текущая страница http://127.0.0.1:3210, предоставленный владельцем скриншот, текущий frontend и API-контракт. Исходные Google-таблицы не использовались и не редактировались.

Распределение: root — клики и визуальная оценка desktop/mobile; независимый проверяющий событий — структура метрик/состояний; независимый проверяющий доступа — роли/выдача прав/навигация. Их выводы проверены на противоречия с текущим контрактом.

Дизайн-основание: конкретный пример владельца «адрес крупнее ракурса» и «метрика → ПТО → время»; существующий стиль кабинета; bundled Refero typography — рабочий инструмент должен легко читаться и сканироваться. Refero MCP в текущем наборе инструментов не доступен. Новый визуальный стиль не разрабатывался.

### 4. Обзор — полезная таблица, но цифры требуют объяснения

Факт: таблица позволяет сравнивать станции, поиск работает. В меню 23 камеры, в сводке 17; подпись уточняет привязку, но смысл различия не очевиден. В одном экране находятся настоящие адреса и демонстрационные 154 въезда/154 выезда.

Предложение: по умолчанию рабочие данные, отдельный режим «Пример данных». Однозначно назвать числа: станции в доступе, камеры в списке, просмотр настроен, анализ настроен. Точные формулировки должны соответствовать измеряемому состоянию: настройка просмотра не доказывает, что камера сейчас передаёт видео. В показателях дня — сколько ПТО имеют результаты за выбранный день; отсутствие анализа не является нулём.

В будущей рабочей сводке полезны быстрые переходы «Начало дня», «Автомобили», «Закрытие», «Требует проверки». Опоздания можно показывать только после задания графиков ПТО и проверки качества анализа; сейчас таких выводов делать нельзя.

## Предлагаемая структура событий

Первый уровень — четыре раскрываемых блока:

| Блок | Что внутри |
|---|---|
| Первое появление и открытие | Одна строка/карточка на ПТО: адрес, первый человек в кадре, время открытия, наличие записи обоих моментов |
| Автомобили | Сначала ПТО и число заездов за обработанный интервал; раскрытие — пары въезд/выезд и время в боксе; отдельная кнопка на каждый момент |
| Закрытие | Адрес, время закрытия, запись; отсутствие результата обозначено причиной |
| Требует проверки | Только спорные/неполные наблюдения с причиной и доступным доказательством |

Фильтры над блоками: день, поиск по адресу, руководитель (когда у пользователя несколько руководителей в зоне). Географический регион — дополнительный фильтр с отдельным названием. Регионалу сначала показывать уже назначенные ему ПТО. Дата интерпретируется по местному времени ПТО; смешивать часовые пояса без подписи нельзя.

Все доступные пользователю ПТО должны оставаться находимыми, включая пункты без результатов анализа. Состояния: «Видео ещё не анализировалось», «Данные неполные», «За обработанный период событий не найдено». Ноль допустим только при подтверждённой обработке периода. Первое появление человека не называть автоматически приходом эксперта.

Внутри связанного заезда: въезд и выезд остаются разными событиями; пара не доказывает уникального клиента. Обе точки открываются отдельно, непарные наблюдения не дополняются выдуманным временем.

## Приоритеты следующей версии

| Порядок | Что изменить | Критерий приёмки |
|---|---|---|
| P1.1 | Адрес главным в карточках, деталях и списках выбора | ПТО определяется по заголовку; ракурс расположен вторым; неизвестный адрес не выдуман |
| P1.2 | События по показателю → ПТО → подробности | Начало работы нескольких ПТО сравнивается без просмотра автомобильной ленты |
| P1.3 | Онлайн сразу под вкладками; доступная камера по умолчанию | В Бийске не возникает ложного впечатления отсутствия онлайн; телефон не требует проходить показатели дня |
| P1.4 | Понятная доступность записей и анализа | Активная кнопка не обещает недоступное видео; «нет анализа» не выглядит как нулевой поток машин |
| P1.5 | Разделить рабочие данные и демонстрацию | Примерные 154 въезда не воспринимаются как результат всей сети; число камер имеет однозначное основание |
| P2.1 | Компактные камеры/поиск/группировка по ПТО | Большие пустые картинки не вытесняют адреса и действия; без запуска всех потоков ради превью |
| P2.2 | Управление доступом с адресным итогом | Директор может проверить, что именно увидит человек; скрытые объекты и права не раскрываются |
| P2.3 | Журнал с фильтрами и сохранение рабочего контекста | Изменение пользователя не возвращает администратора к демонстрационной дате и не сбрасывает допустимые фильтры |
| P2.4 | Короткие подписи состояния просмотра | Подключаемся/повторяем/пауза/прямой эфир/ошибка различаются; прогресс не выдумывается, срок сеанса виден |

Не добавлять первым этапом: новые типы ролей, конструктор прав, сложные графики, распознавание лиц, десятки уведомлений, фоновое включение всех камер. Раздел «Требует проверки» сначала должен быть понятным; полноценные подтверждения/комментарии можно реализовать отдельным коротким шагом, когда есть реальные результаты анализа.

Для подтверждённого покрытия анализа или статуса записей может потребоваться дополнение API; это не считается реализованным данным аудитом.

На текущем этапе создан только этот отчёт и снимки экранов. Тесты кода не запускались: рабочий код не менялся.
