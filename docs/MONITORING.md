# Мониторинг камер

## Пользователь

Откройте «Мониторинг» и добавьте нужные камеры. Сетка подбирает размер плиток по ширине и высоте экрана. «Снять все» очищает текущий набор, включая камеры, скрытые поиском.

По кнопке «Создать стол» пользователь задаёт своё название. Первый стол может принять текущий набор камер. После переключения открывается сохранённый набор выбранного стола, а эфиры предыдущего завершаются. Новый эфир запускается по кнопке. Столы хранятся в текущем браузере отдельно для каждой учётной записи. Из наборов исключаются камеры, к которым пропал доступ.

В сетку можно добавить все доступные для эфира камеры. Кнопка группового запуска учитывает предел одновременных подключений. Остальные плитки остаются в наборе. При удалении карточки или уходе со вкладки её соединение закрывается. Один сеанс длится до 10 минут, затем его можно запустить снова.

Кнопка «Скрыть описание» оставляет в плитках только видео. Общее управление остаётся над сеткой, в том числе в полноэкранном режиме. «Показать описание» возвращает подписи и управление отдельными камерами без перезапуска эфиров.

## Настройка программистом

`PILOT_LIVE_MAX_STREAMS` задаёт общий предел подключений в одном процессе кабинета, от 1 до 150. Значение по умолчанию 1. Предел разделяют все пользователи и одиночные просмотры. Билет на подключение занимает место до использования или истечения срока. Билеты и потоки привязаны к пользователю, сессии входа и разрешённой камере.

В `.env` для ручного многокамерного испытания можно задать `PILOT_LIVE_MAX_STREAMS=5`. Compose передаёт значение приложению. Нужна включённая видеосреда Xiaomi и соответствующие приватные маршруты; обычный контейнер без видеозависимостей не получает видео от этой настройки.

Каждый эфир запускает процессы Python, Java и FFmpeg и перекодирует видео. Размер плитки не влияет на эту нагрузку. Перед увеличением предела измерьте CPU, память, число процессов и трафик при одновременном запуске. В локальном испытании 10.11.2026 пять эфиров занимали около 2,1 ГиБ без браузера.

Для показа более пяти эфиров с одной страницы настройте HTTPS и HTTP/2 на прокси. В HTTP/1.1 отдельный эфир занимает соединение, а Chromium по умолчанию открывает до шести соединений к хосту. При явно определённом HTTP/1.1 интерфейс оставляет одно соединение для управляющих запросов. Для HTTP/2 проверьте предел одновременных запросов на прокси и оставьте запас для команд и загрузки списка камер. [Исходный код Chromium](https://chromium.googlesource.com/chromium/src/%2B/refs/heads/main/net/socket/client_socket_pool_manager.cc), [документация Nginx](https://nginx.org/en/docs/http/ngx_http_v2_module.html#http2_max_concurrent_streams).

API session/login сообщает `liveLimits:{maxStreams}`. Остальные маршруты POST/GET/DELETE live сохранены. При занятом пределе новый запрос возвращает 409 `LIVE_BUSY`; повтор камеры в том же входе — 409 `LIVE_DUPLICATE`. Слот занят до фактического завершения дочернего моста. Выход, отзыв прав, удаление маршрута, отключение клиента и остановка сервера завершают соответствующие соединения.

## Приёмка

Проверить две, затем пять разных камер с реальным движущимся изображением. При ошибке одного источника остальные продолжают работать. Удалить одну карточку и остановить весь набор, убедиться в завершении дочерних процессов. Уйти со вкладки, вернуться, проверить сохранение выбора и отсутствие самозапуска. Проверить узкий экран, полноэкранный режим и переключение «Скрыть описание» во время эфира. Пользователь без права на камеру не должен получать ни список этой камеры, ни её поток, даже по скопированному билету.

Тесты с локальными подставными потоками подтверждают жизненный цикл и доступ, но не заменяют проверку Xiaomi и измерение ресурсов. Измеренные результаты локального испытания записываются отдельно после выполнения.
