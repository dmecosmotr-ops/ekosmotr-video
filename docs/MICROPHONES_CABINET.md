# Микрофоны в кабинете ПТО

Кабинет принимает готовые отчёты по сменам через закрытый каталог. Аудиосервис сохраняет свой процесс обработки и GigaAM. Кабинет не принимает звук, не запускает распознавание и не сверяет оплаты.

## Посмотреть на Windows

Из каталога кабинета запустить `.\start-microphones-demo.ps1`. Нужны Node 24, установленные зависимости frontend и Python с ReportLab для генерации учебных PDF. В среде Codex скрипт подбирает встроенные Node и Python; для другого Python можно передать `-Python <путь>`.

Открыть [локальный кабинет](http://localhost:3211/#microphones), на экране входа выбрать «Администратор» и нажать «Войти». В сводке будут две готовые смены, одна в обработке и одна явно отмеченная без данных. Выбрать регион и ПТО, перейти к сменам станции, открыть PDF. В нём три части: сводка, разговоры с таймкодами, расшифровка. Для камеры и отчёта используется один и тот же вход. Все адреса, реплики и числа в этом запуске вымышлены. Учебные файлы, отдельная БД и PID остаются в `private/microphones-localhost/`. Порт 3210 и его БД скрипт не использует.

## Подключить рабочий отчёт

1. Ответственный за аудио подтверждает `stationId` из справочника кабинета, дату смены по местному времени ПТО и право использовать конкретный PDF. Привязка PDF от 14.10.2026 к станции пока не подтверждена. Кабинет не определяет её по дате, тексту или имени файла.
2. В отдельный приватный каталог, доступный кабинету только для чтения, положить готовый PDF и `catalog.json`. Корень каталога не должен быть статической папкой сайта, её подкаталогом или родительской папкой. Не давать кабинету доступ к архиву исходного звука. Не размещать файлы в Git, статике сайта или Docker-образе. На Linux обеспечить чтение UID/GID `1000:1000`.
3. Для запуска Node указать `PILOT_MICROPHONE_DIR`. Для Docker Compose задать `PILOT_MICROPHONE_DIR_HOST` и использовать дополнительный файл `compose.microphones.yaml` вместе с обычными файлами развёртывания. Например, перед передачей программисту проверить конфигурацию командой `docker compose -f compose.yaml -f compose.microphones.yaml config --quiet`. Само подключение выполняет программист компании.
4. В кабинете администратор открывает «Пользователи», редактирует пользователя и отмечает ПТО в блоке доступа к микрофонам. Включить доступ нужно и для собственной учётной записи администратора. Для остальных ролей список дополнительно ограничен их действующим доступом к ПТО. Назначение отдельной камеры не расширяет этот список. Если доступ отозван, новые запросы отчёта с той же сессией тоже отклоняются.

### Контракт файла `catalog.json` версии 1

Пример структуры; `pto_example` нужно заменить на подтверждённый ID станции.

```json
{
  "version": 1,
  "shifts": [
    {
      "id": "shift-example-2026-10-14-a",
      "stationId": "pto_example",
      "date": "2026-10-14",
      "status": "ready",
      "pdf": "report-example.pdf",
      "metrics": {
        "offerEpisodes": null,
        "sales": null,
        "products": {
          "first_aid_kit": {"offerEpisodes": null, "sales": null},
          "fire_extinguisher": {"offerEpisodes": null, "sales": null},
          "warning_triangle": {"offerEpisodes": null, "sales": null},
          "license_plate_frames": {"offerEpisodes": null, "sales": null}
        }
      }
    }
  ]
}
```

- `id` уникален для смены. `stationId` — точный ID из справочника. `date` — календарная дата на станции. Статусы: `ready` — готовый PDF, `processing` — обработка, `missing` — явно известная смена без отчёта. Для последних двух не указывать PDF и метрики. Без реестра ожидаемых смен кабинет не может перечислить пропущенные смены или вывести процент покрытия сети.
- `pdf` — уникальное простое имя файла `.pdf` в том же каталоге. Без URL, подкаталогов, абсолютных путей и символических ссылок. Сначала записать PDF под новым именем, затем атомарно заменить каталог целиком после записи во временный файл на том же диске. Опубликованный PDF нельзя перезаписывать, а его имя нельзя переиспользовать: запрос, который ещё читает прежний каталог, должен видеть прежнюю версию файла. Учебные записи с `demo: true` допустимы только в локальном режиме; не смешивать с рабочими сменами.
- `offerEpisodes` — число эпизодов с подтверждённым предложением; один эпизод может фигурировать в нескольких строках товаров. `sales` — число подтверждённых продаж; согласие купить и обсуждение цены продажи не подтверждают. Использовать `null` для неизвестных метрик и `0` только для подтверждённого нуля. Кабинет не извлекает цифры из PDF и показывает «Нет данных», если достоверных структурированных чисел нет. При частичных данных сводка показывает, сколько готовых отчётов вошло в показатель.

Проверка после подключения: одна учётная запись открывает «Камеры» и «Микрофоны», фильтр по ПТО показывает его смену, PDF читается из кабинета. Скопированная прямая ссылка возвращает отказ без входа, для пользователя только с камерой и для пользователя с доступом к другому ПТО. Проверить это повторно после отзыва доступа. Проигрыватель звука появится только после появления отдельного защищённого источника.
