# Камеры из общих домов Xiaomi

Импорт получает камеры из существующего Xiaomi-аккаунта, включая приглашения в дом. Камеры с одинаковыми именами различаются по идентификатору устройства. Настройки доступа пользователей к ПТО хранятся в кабинете.

## Автосинхронизация на сервере

После подключения сервера принимайте приглашения в том же Xiaomi-аккаунте. Отдельный процесс проверяет этот аккаунт каждые пять минут по умолчанию. Кабинет применяет готовый список без перезапуска. Если открыт раздел с камерами, браузер подхватит изменения при следующем обновлении списка, обычно в пределах 30 секунд после успешной синхронизации.

При первом запуске программист готовит каталоги с доступом для пользователя контейнера UID 1000 и GID 1000:

| Каталог на сервере | Содержимое |
| --- | --- |
| `private/xiaomi-session` | Файл `go2rtc.yaml` с действующей сессией Xiaomi нужного аккаунта |
| `private/xiaomi-config` | `sync-config.json` и `live-bridge.json` из шаблонов в `deploy/`, при необходимости `station-map.json` |
| `private/xiaomi-vendor` | Только проверенные и разрешённые к использованию Java-классы видеотранспорта с исходной структурой каталогов |
| `private/xiaomi-relay` | Пустой каталог для сборки Java-моста, доступный на запись UID 1000 |

Скопируйте `deploy/xiaomi-sync.json.example` в `private/xiaomi-config/sync-config.json`, а `deploy/xiaomi-live-bridge.json.example` в `private/xiaomi-config/live-bridge.json`. Укажите реальный ID аккаунта только в локальном `live-bridge.json`. Контейнерные пути в шаблонах уже соответствуют настройкам Compose. Приватные файлы передаются на сервер отдельно от GitHub. При обычной установке сначала выполните настройку `.env` и пароля администратора из [SERVER_DEPLOYMENT.md](SERVER_DEPLOYMENT.md).

```bash
docker compose -f compose.yaml -f compose.xiaomi.yaml build camera-pilot
docker compose -f compose.yaml -f compose.xiaomi.yaml run --rm xiaomi-relay-build
docker compose -f compose.yaml -f compose.xiaomi.yaml up -d camera-pilot xiaomi-sync
docker compose -f compose.yaml -f compose.xiaomi.yaml logs --tail 30 xiaomi-sync
```

Первый импорт запускается при старте. Поле `intervalSeconds` задаёт паузу между синхронизациями и принимает значения от 60 до 3600. При ошибке Xiaomi кабинет оставляет последний успешно полученный список. Если полный успешный запрос показывает, что доступ к камере отозван, камера исчезает из синхронизируемого каталога. Если Xiaomi потребует повторного входа, обновите `go2rtc.yaml` в том же каталоге сессии.

Новые камеры сначала видны администратору. Для подтверждения связи с ПТО добавьте в `sync-config.json` поле `stationMap` со значением `/run/private/config/station-map.json`. В карте укажите пары `{ "идентификатор_камеры": "идентификатор_станции" }`. После добавления поля один раз перезапустите `xiaomi-sync`. Правки самой карты подхватятся при следующей успешной синхронизации. Проверка адреса нужна перед выдачей доступа по станции.

На сервере отдельно проверьте импорт пилотных камер и ручное открытие живого видео. На исходном компьютере прямое соединение по Wi‑Fi позволило получить список камер и параметры видеоподключения. Пробный запуск потока пока не дал кадров. Для HTTPS-прокси нужны ожидание первого ответа не менее 120 секунд и отключённая буферизация видеопотока.

## Ручная подготовка локального кабинета

Нужны приватный YAML существующей сессии Xiaomi, зависимости из `tools/requirements-diagnostic.txt` и рабочий шаблон `live-bridge.json`. Шаблон содержит регион, идентификатор аккаунта, абсолютные пути к FFmpeg, Java, собранному мосту и его зависимостям. Поля `deviceId` и `model` заменяются при сборке маршрутов. Для первого запуска можно указать в шаблоне условные значения `1` и `xiaomi.camera.placeholder`. Файлы сессии, параметры камер и выходные конфигурации храните в `private/`.

Из корня `camera-pilot`:

```powershell
python tools/xiaomi_shared_inventory.py --region ru --config private/go2rtc.yaml --output private/xiaomi-shared-inventory.json --legacy-inventory private/camera-inventory.json
python tools/xiaomi_cabinet_bundle.py --snapshot private/xiaomi-shared-inventory.json --bridge-template private/live-bridge.json --legacy-inventory private/camera-inventory.json --legacy-live private/live-config.json --output-dir private/xiaomi-cabinet
.\start-pilot.ps1 -XiaomiBundle private/xiaomi-cabinet
```

При первой установке пропустите оба флага `--legacy-inventory` и флаг `--legacy-live`. Если PyYAML установлен в отдельном каталоге, передайте его через `--python-deps` первой команде. При обновлении создайте комплект в новой папке, например `private/xiaomi-cabinet-next`, остановите пилот и выберите новую папку при следующем запуске. При неполном ответе Xiaomi импорт завершается с ошибкой и сохраняет предыдущий снимок.

Администратор видит все карточки комплекта. Чтобы дать доступ по ПТО, передавайте второй команде `--station-map private/station-map.json` при каждой сборке. Формат файла — объект `{ "идентификатор_камеры": "идентификатор_станции" }`. Используйте ID из локальных `camera-inventory.json` комплекта и `data/stations.json`. Подтвердите по видео и адресу, что это нужное устройство. Прежние карточки сохраняют существующие привязки при передаче `--legacy-inventory`.

Если Xiaomi не отдаёт список домов, владелец может поделиться нужной камерой прямо из её карточки. Для такой проверки запустите импорт с `--direct-only` и укажите новый файл снимка. Этот режим читает прямой список устройств, а исходный снимок общих домов остаётся доступен.

## Проверка просмотра

1. Войдите как администратор и найдите камеру в разделе «Камеры». Непривязанные камеры собраны в группе без адреса.
2. Нажмите «Онлайн». Дождитесь кадров и проверьте, что время воспроизведения идёт. Остановите просмотр и проверьте следующую камеру. Одновременно кабинет обслуживает один просмотр.
3. Для привязанной камеры проверьте доступ из учётки с разрешением на это ПТО и отсутствие доступа из учётки без него.

Открытие карточки и наличие кнопки означают, что маршрут настроен. Фактическая доступность проверяется при каждом запуске. Существующий мост принимает H.265 через транспорт CS2 (vendor 4) и выдаёт H.264 для браузера. Совместимость конкретной камеры подтверждается получением кадров. Разные модели и сетевые подключения могут дать разный результат.

На Linux выполняйте команды сборки комплекта в среде, где будет работать процесс Node. Задайте `PILOT_CAMERA_INVENTORY` и `PILOT_LIVE_CONFIG` абсолютными путями к одноимённым файлам комплекта. Кабинету с онлайн-просмотром нужны Node, Python, Java, FFmpeg и исходящий доступ к Xiaomi и видеоретранслятору в одной выделенной среде. Стандартный контейнер кабинета предназначен для запуска без этих зависимостей, а отдельный контейнер приёма видео выполняет разовые задачи записи. Схему размещения на сервере проверяет программист. Если используется HTTPS-прокси, для маршрута онлайн-видео задайте ожидание первого ответа не менее 120 секунд и отключите буферизацию потока.
