# Приём видео и первый анализ — 05.11.2026

## Цель и проверяемый результат

Подготовить пункты 3 и 4 параллельно с установкой кабинета. Отдельный процесс записывает ограниченный материал одной выбранной камеры, Python-анализатор действительно запускает нейросеть на видео, а Node-кабинет показывает результаты и защищённую запись по существующим ролям. Программист компании проверяет и устанавливает обновление; доступа к серверу у исполнителя нет.

Пользователь поручил готовить это сейчас. Существующий кабинет, его роли, локальный онлайн и основной Docker-запуск сохраняются. Никакого автоматического подключения 70 камер или фоновой записи по умолчанию.

## Выбранный подход и границы

Используем завершённые небольшие отрезки и отдельные приватные файлы результатов. Это позволяет проверить детектор и счётчик до переноса камеры на Linux. Общая БД пользователей не доступна анализатору. Непрерывная служба раздачи одного потока всем зрителям потребовала бы отдельного управления очередями; она не нужна для этой первой проверки.

Нейросеть — YOLOX Nano в ONNX Runtime на CPU; GPU не обязателен для одиночной функциональной проверки. Это выбор реализации, не измеренная вместимость сервера. Источник модели и Apache-2.0: официальный YOLOX, https://github.com/Megvii-BaseDetection/YOLOX/blob/main/demo/ONNXRuntime/README.md и LICENSE. Модель скачивается отдельно с проверкой SHA-256; веса и частные записи не входят в Git. Зависимости анализа находятся в отдельном окружении/образе.

Существующий диагностический Xiaomi-мост использует отдельно предоставленные `micam.*`. Их происхождение, разрешение на распространение и Linux-работа не подтверждены: не скачивать их автоматически, не публиковать и не обещать готового подключения. Подготовить Linux-проверку, сборку нашего Java-класса и конфиги без секретов. Авторизация Xiaomi передаётся на сервер защищённым способом вне Git.

## Метрики

- `first_seen`: первое устойчивое обнаружение человека в настроенной зоне **в обработанном фрагменте**. Личность и начало смены не устанавливаются.
- `vehicle_entry` / `vehicle_exit`: подтверждённый трек пересёк настроенную линию в одном из направлений. Не считать просто найденные автомобильные кадры. Связанный въезд/выезд получает общий visitId только при непрерывно наблюдаемом треке; потерянный трек не склеивать по времени.
- `opened` / `closed`: необязательная калибровка области ворот по двум частным изображениям открытого/закрытого состояния с несколькими устойчивыми наблюдениями. Событие означает предполагаемое изменение состояния ворот и требует проверки. Без калибровки/уверенности открытие и закрытие остаются неизвестными. Пустой кадр не доказывает закрытие.
- Все новые результаты предварительные, с `needsReview:true`, моделью/версией, ссылкой на запись и смещением. Один автомобиль не равен одному клиенту. Основная камера счётчика назначается явно, два ракурса не складываются.
- Данные одного фрагмента всегда `partial`: наблюдения не выдаются за итог дня. Отсутствие найденных событий не превращается в ноль за смену.
- UTC хранится вместе с IANA timezone. Адаптер UI выдаёт локальные `date` и `time:HH:mm:ss`. Существующий Xiaomi-мост генерирует 20fps без исходных временных меток: время такого материала `estimated`, точные часы открытия/закрытия не подтверждаются.

## Общий контракт v1

Приватная конфигурация кабинета `PILOT_ANALYSIS_CONFIG`:

```json
{
  "resultsDir": "/video/results",
  "archiveRoot": "/video/recordings",
  "cameras": [{
    "cameraId": "pilot-camera-1", "stationId": "confirmed-station-id",
    "mappingVersion": "v1", "timezone": "Asia/Barnaul",
    "name": "Камера бокса", "model": "Xiaomi C300", "primary": true
  }]
}
```

stationId должен существовать в реестре, primary только один на ПТО. Это отдельная подтверждённая привязка, она не зависит от переименований Xiaomi. Идентификатор не содержит DID/URL/токен.

Анализатор атомарно пишет `<runId>.json` в resultsDir:

```json
{
  "schemaVersion": 1, "runId": "opaque-run-1", "pipelineVersion": "yolox-nano-v1",
  "cameraId": "pilot-camera-1", "stationId": "confirmed-station-id",
  "mappingVersion": "v1", "timezone": "Asia/Barnaul",
  "generatedAt": "2026-11-05T04:05:00.000Z",
  "recording": {
    "id": "opaque-run-1", "file": "opaque-run-1/video.mp4", "sha256": "64-lowercase-hex",
    "startedAt": "2026-11-05T04:00:00.000Z", "durationSeconds": 300,
    "timing": "estimated"
  },
  "coverage": {"status": "partial", "sampleIntervalSeconds": 1},
  "events": [{
    "id": "opaque-run-1-event-1", "type": "vehicle_entry",
    "occurredAtUtc": "2026-11-05T04:01:02.000Z", "confidence": 0.8,
    "visitId": null, "needsReview": true,
    "evidence": {"recordingId": "opaque-run-1", "offsetSeconds": 62}
  }]
}
```

runId/recordingId/eventId — короткие непрозрачные ASCII идентификаторы. Манифест не содержит произвольных команд, внешних ссылок или абсолютного пути видео. Backend читает только ограниченное число небольших JSON из configured resultsDir, проверяет соответствие cameraId/stationId/mappingVersion/timezone, времён, смещений и расположение архива. Несовместимый/повторный run отклоняется или дедуплицируется; неоднозначные перекрывающиеся интервалы не суммируются. Права `canCamera` применяются до агрегации. Никакого HTTP импорта команд или ключей.

Collector создаёт `<archiveRoot>/<runId>/video.mp4` и соседний `capture.json` с schemaVersion, runId, cameraId/stationId/mappingVersion/timezone, relative file, sha256, startedAt (первый байт), durationSeconds из ffprobe, timing estimated, timestamps начала/конца получения и статусом. Только успешно завершённый валидный отрезок может перейти в анализ. Обрезанный/пустой/превысивший лимит файл не регистрируется как успешный. Для записанного файла с известным исходным временем разрешён отдельный анализ с явным startedAt/timing; это не доказательство корректности часов камеры.

## Приёмка

- Настоящий вызов ONNX Runtime на публичном тестовом изображении с сохранёнными версиями/хешем, временем и найденными классами; это функциональный smoke, не проверка точности ПТО.
- Синтетические последовательности: въезд, выезд, одинаковый visitId, дрожание возле линии, разворот, потеря трека, разные классы, неполный материал, устойчивость человека и калибровка ворот.
- Backend: чужая камера/скрытые агрегаты, смена даты/таймзоны, неверная привязка, повторы/перекрытия, невалидные результаты, traversal/симлинки, неизвестный архив, ограниченные Range запросы, сохранение demo/live/probe.
- Collector: конечный synthetic subprocess, timeout/stall/byte/disk limit, сигнал остановки, отсутствие регистрации незавершённого видео, завершение дочерних процессов. Отдельно Linux контейнерный smoke при доступности CI.
- Полные Node/Python тесты, frontend build и source scan. Не загружать реальные записи/модели/секреты в Git.
- Независимый review новых путей данных и deployment. Запуск в компании, реальная Xiaomi-сессия на Linux, качество на ПТО, точность часов и производительность всей сети остаются отдельными измерениями, а не обещанием.
