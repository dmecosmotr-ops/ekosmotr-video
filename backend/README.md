# Backend локального пилота

Node.js 24 со встроенными `http`, `crypto`, `sqlite`; дополнительных backend-пакетов нет. Запускать `node apps/camera-pilot/backend/server.mjs` из корня проекта. Frontend сначала собирается в `frontend/dist` и отдаётся тем же процессом.

По умолчанию сервер слушает только `127.0.0.1:3210`. Настройки окружения: `PILOT_PORT`, `PILOT_DB`, `PILOT_STATIONS`, `PILOT_PROBE_MEDIA`, `PILOT_CAMERA_INVENTORY`. Media указывает на уже разрешённый локальный MP4 проверки, не на Xiaomi URL. Видео не скачивается, камера и облако не вызываются.

API и начальные тестовые аккаунты описаны в `../CONTRACT.md`. Пароли хранятся как scrypt-хеши с отдельной солью; cookie-сессии — случайные значения, в SQLite сохраняется только хеш session token. Mutations требуют CSRF, пользователь и его права перечитываются на каждый запрос. API и видео не кэшируются. Не публиковать этот локальный стенд в Интернет как готовый production-сервис.

Администратор управляет любыми ролями. Директор управляет только созданными им региональными пользователями и выдаёт им свои станции/камеры. Региональный пользователь — просмотр. Полная станция разрешает все её камеры, отдельная камера — только себя и сведения о станции. Непривязанный `probe-c300` доступен только администратору.

Директорские выдачи помечаются `delegated_by`: эффективные права пересекаются с текущим набором прав активного директора на каждом запросе. Деактивация, понижение роли или отсутствие директора убирает делегированный доступ. Права, назначенные непосредственно администратором, от этой цепочки не зависят. Фактическое изменение роли/эффективного набора станций/камер администратором переносит выдачу под его управление; неизменённые значения полного UI payload, изменение имени, пароля или активности источник прав не меняют. Множества прав сравниваются без учёта порядка, а сохранённый намеренный scope при name-only edit не сжимается. Старые БД пилота получают миграцию колонки при запуске.

Пять камер с `status=demo` и события 30.10.2026 являются учебными. В демонстрации въезд и выезд связаны `visitId`; время в боксе считается только для однозначной пары той же камеры/станции/дня, после фильтрации прав. Непарные наблюдения остаются непарными. Метрики `entries`, `exits`, `completedVisits` не измерены на реальных ПТО; остальные даты возвращают `source=none` и `null`.

`PILOT_CAMERA_INVENTORY` — необязательный JSON-массив безопасных `{id,name,model}`. `createApp` получает его через `inventoryFile`. Лишние поля не попадают в API, встроенные ID нельзя заменить, повреждённый/пустой файл не останавливает пилот. Только `camera-matching.mjs` сопоставляет названия с реестром: имена не доказывают наличие видеопотока, нужный ракурс или исправность камеры. Импортированные камеры всегда `unconnected`, `view=unknown`, метрики отсутствуют. Неоднозначные и непривязанные камеры видит только администратор.

`GET /api/cameras/:id/playback` сообщает раздельные состояния онлайн и архива. У одной настроенной камеры live.status=available; это разрешение ручного запроса, не обещание доступности24/7. У остальных live.status=not_connected и URL=null. Только `probe-c300`, если настроен существующий файл, имеет архивный клип: 30.10.2026 12:21:28–12:21:38.350, 10,35 с, `camera_local_unverified`. Часовой пояс и адрес не установлены. `sampleRange` заканчивается в 12:21:39 для совместимости с поиском `HH:mm[:ss]`; сам результат обрезается точно по 10,35 с. `GET /api/archive?cameraId=...&date=...&from=...&to=...` валидирует интервал одного дня и возвращает пересечение с клипом и смещения внутри файла. За пределами этого клипа ответ `empty` относится только к подключённому пилотному материалу. Для остальных камер `not_connected` не означает, что записей на камере нет. Медиа, поиск и playback проверяют одинаковые права.

Нет распознавания личности, реального ИИ, видеоприёма24/7 или полного облачного архива. Поздним запросом03.11 добавлен ручной диагностический live для одной C300 через PILOT_LIVE_CONFIG: session-bound POSTticket/GETfMP4/DELETEstop, max600s, startup110s, stall15s, права проверяются каждую секунду. ПослеStop и при shutdown ожидается очистка subprocess; rawstderr/команды/ключи не отдаются. Обновлённый контракт — ../CONTRACT.md. Первоначальная регистрация playback с not_connected теперь переопределяется live.available только для настроенной камеры; архивный probe по-прежнему отдельный.

Проверки: `node --test apps/camera-pilot/tests/*.test.mjs apps/camera-pilot/frontend/*.test.mjs` —94/94PASS, отдельно9Pythonbridge. Они создают временные синтетические данные, сессии и mediafixtures, проверяют HTTP/RBAC/CSRF, пары событий, архив/смещения, импорт и lifecyclelive; реальные записи не читаются.
